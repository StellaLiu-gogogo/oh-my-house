# Household Companion — Notification Delivery Rules v0.1

- **日期：** 2026-08-27
- **阶段：** Product Design
- **状态：** 第一阶段规则已由用户确认
- **范围：** 多成员、多设备情况下提醒发送给谁

## 1. 基本原则

通知不是发给一个抽象的 household，而是根据内容的负责人和家庭范围发送到相应成员连接的设备。

通知权限仍由每台设备自己控制。某台设备关闭通知，不会关闭其他成员设备的通知。

## 2. Chores

- 一人负责：发送给该成员；
- 多人共同负责：发送给所有负责人；
- 无人负责：不推送个人提醒，只在 Today 显示；
- 轮流负责：每次只发送给该次实际负责人。

## 3. Maintenance

- 有一位或多位负责人：发送给所有负责人；
- 无负责人：不主动推送，只在 Today 显示；
- 完成当前一次后，后续重复维护按照下一次负责人继续处理。

## 4. Household Events

Household Event reminder 默认发送给所有已连接家庭使用者。

Event reminder 不会因为某位成员当前没有打开 App 而改为只发送给创建者。

## 5. Shopping

Shopping 第一阶段不自动发送通知。

添加商品、合并商品或标记 Purchased 不向所有成员广播，避免日常操作产生过多提醒。

## 6. 语言

每台接收设备按照其关联 Member 的默认语言显示通知。

用户创建内容保留原文并使用已有翻译；翻译暂时不可用时显示原文，通知仍然发送。

## 7. 每台设备自己的设置

以下内容不在设备间强制同步：

- 系统通知权限；
- 通知是否被系统静音；
- 当前使用的 Member；
- 临时显示语言。

## 8. 可以以后决定

- Meal-related reminder 的具体场景和接收对象；
- Event 是否允许选择部分接收成员；
- Shopping 是否允许手动发送“我要去购物”的通知；
- 每位成员的免打扰时间；
- 通知汇总方式。

这些增强不影响第一阶段规则。
